# 수정·검증 범위

시작점: `origin/claude/integrate-fire` **8a2efaa**를 `codex/barista-restore`에 fast-forward로 반영했습니다.

## 다섯 가지

1. **거스름돈**: 금액별 지폐/동전을 겹치지 않는 칸에 놓습니다. 같은 금액을 여러 번 고르면 장수/개수를 함께 표시합니다. 새로 고르기와 다시 열기 모두 같은 배치 함수를 씁니다. 금액 버튼, 하나 빼기, 합계, 묶음 끌기는 유지합니다. 직접 만 원을 받아 5천 원+천 원을 고른 뒤 손님에게 끌어 건네 결제 완료를 확인했습니다.
2. **붓기**: 컵 근처로 끌면 피처 몸통은 컵 오른쪽 위·머신 앞에 머물고 주둥이가 컵을 향합니다. 물줄기는 주둥이 끝에서 실제 컵 수위로 이어집니다. 손을 떼면 붓기가 멈추고 피처가 제자리로 돌아갑니다. 물과 우유 각각 직접 끌어 사진을 남겼습니다. 안내 표시는 유지하되 붓는 컵을 따라 덮지 않게 했습니다.
3. **수도꼭지**: 꼭지/손잡이에 직접 누르기·놓기를 하면 켜지고 다시 누르면 잠깁니다. 드래그하거나 취소한 입력은 전환하지 않습니다. 아래 수도 버튼과 같은 상태를 쓰고 손잡이 각도·색도 바뀝니다. 직접 켜기→잠그기→켜기를 확인했습니다.
4. **선반 정리**: 선반의 화면 영역+여유 범위로 놓기를 판단하며 마지막 pointerup 좌표도 반영합니다. 컵을 끄는 동안 높이를 올리고, 선반 가까이에서는 놓을 자리의 원이 반응합니다. 선반 위에 컵이 올라가며 뒤판과 안내가 컵 입구를 가리지 않습니다. 씻기 전 컵도 선반 아래로 파고들지 않게 앞쪽에 두었습니다. 폰에서 문지르기→헹구기→건조대→선반 완료. PC에서 똑같이 보이는 선반 오른쪽 끝으로 끌었을 때 **이전 판은 건조대로 돌아가고 수정 판은 선반에 놓이는 것**을 확인했습니다. 이전 판도 선반 가운데에 놓는 경우는 성공했으므로 모든 놓기가 실패했다고 쓰지 않습니다.
5. **손님**: 지우는 어깨까지 내려오는 머리와 카디건, 서연은 묶은 머리와 후드, 민준은 짧은 곱슬머리와 조끼입니다. 옷의 형태·머리·피부색을 구분했습니다. 기존 걷기·앉기·표정·마시는 팔 구조는 그대로입니다. 비교 사진은 실제 게임의 person()으로 만든 세 인물을 같은 전시 각도에 놓았습니다.

## A14·A15·A17 확인 방법

- 새로 `display:none`/`hidden`으로 감춘 안내는 없습니다. 장소 표시·제목·수도 버튼을 유지했습니다.
- Ego 브라우저의 폰 크기 390×844 / PC 1280×800에서 스크린샷을 보고 누를 곳과 끌 경로를 정했습니다. 마우스 press→move→release 이벤트를 보냈고, 앱의 3D 좌표를 계산하거나 `move/up/storeCup` 함수를 직접 호출해 동작을 통과시키지 않았습니다. 모바일 화면 배율에서 기본 마우스 래퍼의 입력이 맞지 않아 같은 브라우저의 CDP 포인터 입력을 사용했습니다.
- `tests/hands-fixture.js`는 로컬 비교 복사본의 game.js에만 붙이는 재현용 시작 상태입니다. 결제는 돈 받기 전, 제조는 에스프레소 추출 후, 세척은 더러운 컵부터, PC 선반 비교는 헹군 컵이 건조대에 있는 상태부터 시작했습니다. **전체 하루 검사로 표시하지 않습니다.** 동작 도중 상태를 수정해 넘기지 않았습니다.
- 원본과 수정 화면을 같은 장면으로 나란히 배치했습니다. 포인터를 누른 중간·놓은 뒤 사진도 README 아래 링크에 남겼습니다. 최종 폰 세척 사진은 마지막 컵 초기 위치 보정 뒤 다시 조작해 촬영했습니다.
- 실제 스마트폰 기기·사람 참가자의 사용성 평가를 했다는 뜻은 아닙니다. 독립적인 전체 하루 재채점은 Claude가 진행해 주세요.
