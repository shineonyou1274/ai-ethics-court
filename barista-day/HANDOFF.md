## 구현된 하루

1. 싱크대에서 손 씻기 → OPEN → 입장 소리와 인사 말풍선.
2. 손님 3명: 지우 아메리카노 4,000원(현금 5,000원), 서연 오트라테 5,000원(카드), 민준 라테 4,500원(현금 10,000원).
3. 받은 지폐를 트레이로 드래그. 5,000/1,000/500/100원을 고르고 거스름돈을 건넴. 틀리면 정정 가능. 카드는 단말기에 드래그. 모두 가상 결제.
4. 결제 완료 → 영수증 출력 → 직접 집어 손님에게 전달 → 감사 말풍선. 영수증 전달 전 제조 불가. 닫고 다시 열어도 이어짐. 매출은 결제 성공 때 단 한 번 증가.
5. 컵 선반에서 컵을 놓고 원두 갈기/추출. 우유 또는 오트 선택/스팀. 피처를 컵 위에 가져가 눌러 붓고 원하는 양에서 멈춤. 액면 상승, 색 혼합, 작은 화면용 컵 단면 표시.
6. 취향과 양에 따라 맛 반응·표정·만족 표시가 달라짐. 손님이 컵을 들고 자리로 이동, 앉아 마신 후 퇴장.
7. 남긴 컵을 직접 수거하고 테이블을 손가락으로 문질러 닦음. 자동 시간 완료가 아님.
8. 수도를 틀어 컵의 커피 자국을 문지르고 흐르는 물에 헹군 뒤 건조대에 놓음. 건조대 → 선반도 직접 이동.
9. 처음 지급된 cup-1 하나를 세 손님에게 순환 사용. 선반에 정리해야 다음 제조 가능. 비운 컵도 버려지지 않고 세척 대기열로 감.
10. 모든 손님 퇴장, 테이블 청소, 컵 선반 보관, 도구/재료 정리 후 퇴근. 일당 확인, 서로 다른 끌린/버거운 순간 선택, 출근 기록 저장.

v13의 위치 수정도 포함했습니다. 좌우 의자는 테이블 쪽을 향하고, 손님은 카운터 바깥(3.5, 1.65), 직원 대화 위치는 안쪽(3.5, -0.65)입니다. 말풍선은 한 번에 하나를 우선 표시하고 HUD/화면 밖을 피합니다.

## shared 게시판 다섯 요청 적용

- 일당은 salaryDay(3004, workedMin, 480)만 사용합니다. 커리어넷 180, 2021년 음료조리사 자료를 명세서에 표시. 8시간 95,840원, 15분 연장 예시 100,330원. 명세서에 careernetUrl('180') 출처 링크와 표본 수/직업 순위 금지 안내를 추가했습니다. 데이터의 최신성 재조사는 이번 범위가 아니며 shared 약속의 값을 그대로 사용했습니다.
- 체험 시계는 완료한 업무 단계에 따라 08:30에서 진행합니다. 정오 휴식 60분은 자동 반영, 정상 퇴근 17:30. 재제조 1회마다 15분 지연. 퇴근 시 선택 전에는 17:30을 유지하고 저장을 막습니다. 남아서 마치기를 고르면 최대 120분 연장, 초과분만 자동 인계합니다. 인계하고 정시 퇴근을 고르면 지연 전부를 인계하고 연장 수당은 0입니다. extra.handedOverMin에 인계 시간을 기록합니다. 힘은 100에서 연장 15분당 4 감소하는 단순 표시이며 extra.energy에 기록합니다. 실제 플레이 경과 초를 노동 시간으로 계산하지 않습니다.
- 퇴근 화면의 큰 숫자는 세전 일당. 가게 매출·재료비·만족 표시는 별도 접힌 영역. profit 계산/표시 제거. 내부 tips 수치는 호환성 때문에 남겼으나 일당에 더하지 않고 extra.satisfaction으로 저장합니다.
- 완료한 하루의 7개 순간에 E/S/R/I/C를 붙였습니다. 일곱 순간을 두 열 카드로 보여 주고 각 카드에서 끌림/버거움을 누릅니다. 끌린/버거운 순간은 서로 달라야 저장됩니다. 설명은 공통 RIASEC.name/what 사용, 판정하지 않는다는 안내 포함.
- makeRecord → checkRecord(빈 배열 확인) → saveRecordSafe 순서. 결과 ok를 확인하고 임시 길이 비교를 제거했습니다. 저장 재시도에도 동일 id를 유지합니다. app=barista-day, place=cafe. 완료 전 기록 생성 금지. 동일 실행의 중복 클릭/화면 재열기로 중복 저장되지 않음. 저장이 막혔으면 성공으로 표시하지 않고 재시도 안내. 저장된 출근 기록에는 개인 정보가 없습니다. 보내기 창에서만 번호나 이름을 입력하고 공통 encodeRecords(loadRecords(), name)로 코드를 생성합니다. 병원 기록도 함께 내보내며 창을 닫으면 이름/코드를 제거합니다. 복사 실패 시 코드 선택과 수동 복사 안내를 제공합니다.

퇴근길 한 줄은 우선순위에 따라 인계 선택 → 연장(초과 인계 여부 구분) → 재제조 → 취향 일치 전체/일부/없음으로 달라집니다. 화면과 기록이 같은 endingFor()를 사용합니다. extra에는 matchedDrinks와 departureChoice도 남깁니다.

## 상태 불변 조건

- payment.paid와 payment.receiptGiven 모두 충족해야 payment.ready. completePayment()는 주문 인덱스별 한 번만 처리.

## 남은 문제 / 다음 작업

1. **실기기 검증:** iOS/Android 저사양 WebGL, 작은 가로 화면, 긴 말풍선, 멀티터치/화면 회전. 현재 앱 브라우저 확인만으로 모바일 전체를 보증할 수 없음.
2. **시계의 깊이:** 업무 단계 점프/자동 휴식/재제조 지연은 임시 교육 모델. 연장 vs 인계 선택은 구현했습니다. 휴식 중 요청과 앞선 판단이 오후에 돌아오는 장면은 미구현입니다. Claude의 판단 흐름과 합칠 주요 지점.
3. **저장:** 완료 기록만 기기 저장. 중간 이어하기, 계정/서버, 다중 탭 동시 저장 충돌 방지는 없음. 교사 수집은 코드 방식으로 결정되어 학생 내보내기를 구현했습니다. 교사용 가져오기/CSV 화면은 career-day 소유입니다. saveRecordSafe를 적용했지만 localStorage의 진짜 동시 read-modify-write는 원자적이지 않아 다중 탭 동시 쓰기 경쟁을 완전히 막지는 못합니다.
4. **손님/콘텐츠:** 고정 세 손님과 메뉴. 처음 요청한 손님 머지 게임·대기열 경영·장기 성장·다양한 직업 연결은 아직 없음.
5. **시각/이동:** 기본 도형 캐릭터, 단순 팔다리 동작. 가구 길찾기는 있지만 NPC끼리 동적 회피는 없음. 의자 자체는 독립 충돌체가 아님.
6. **수동성:** 제조·청소·컵 세척·결제는 직접 조작하지만 준비 손 씻기와 일부 도구/재료 마감은 시간/버튼 기반. 대체 모드는 슬라이더/버튼/문지름으로 더 단순함. 3D와 동일한 손동작 품질을 제공하지 않음.
7. **코드 품질:** game.js 단일 파일과 누적 CSS를 장면/입력/HUD로 분리할 필요. 자동 브라우저 E2E는 아직 없고 Node와 수동 QA를 조합.
