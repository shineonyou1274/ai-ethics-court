# 직업체험 앱 약속 (v1)

여러 직업체험 앱(지금은 **오늘, 출근합니다**와 **한 잔의 하루(바리스타)**)이 나중에 하나로 묶일 수 있도록 함께 지키는 약속이에요.
코드로 된 약속은 `shared/workday.js` 하나이고, 이 문서는 그 까닭과 나머지 약속을 적어요.

## 0. 하나로 묶었을 때의 모습

> 학생이 여러 일터에 하루씩 출근해서 직접 일하고, 퇴근하면 **그날의 일당**을 받는다.
> 출근할 때마다 지갑이 쌓이고, 퇴근길에 **끌린 순간과 버거운 순간**을 고르며 나의 흥미를 살핀다.
> 교사는 학생들의 **출근 기록**을 모아 진로 수업에 쓴다.

- 일당은 끝까지 참여하게 하는 **노동의 대가**예요. 그래서 일당은 실제 통계로 계산하고, 계산 방법도 화면에 밝혀요.
- 앱마다 잘하는 것이 달라요. 서로 빼앗지 않고 나중에 섞어요.
  - **한 잔의 하루**: 손으로 직접 하는 일이 살아 있음. 원두를 갈아 추출하고, 붓는 양을 맞추고, 손님을 받고, 컵을 씻고, 테이블을 닦아요.
  - **오늘, 출근합니다**: 판단의 결과가 이어짐. 앞의 선택이 오후에 돌아오고, 게이지와 밀린 시간이 바뀌어요.
  - 하나로 묶을 때는 일터마다 **손으로 하는 일 + 판단과 그 결과**가 함께 들어가는 걸 목표로 해요.

## 1. 일당 (꼭 지킬 것)

`shared/workday.js` 의 `salaryDay(연봉, 일한 분, 약속된 분)` 로만 계산해요. 앱 안에서 따로 계산하지 않아요.

| 규칙 | 값 |
|---|---|
| 자료 | 커리어넷 직업정보의 평균 연봉(중앙값, 만 원) |
| 시급 | 연봉 ÷ 12 ÷ 209시간, 10원 단위 반올림 |
| 최저 시급 | 계산한 시급이 2026년 최저 시급 10,320원보다 낮으면 최저 시급 (명세서에 까닭을 밝힘) |
| 기본급 | 시급 × 약속된 근무 시간 (보통 8시간) |
| 연장 수당 | 8시간을 넘긴 시간 × 시급 × 1.5, 최대 2시간 |
| 쉬는 시간에 일함 | 일한 시간에 넣음 |
| 표시 | 모두 **세전**. 직업끼리 순위를 매기지 않음 |

**바리스타 값**: 커리어넷 코드 `180`, 연봉 3,004만 원(2021년, 음료조리사 기준) → 시급 **11,980원**, 8시간 기본급 **95,840원**.

### 매출과 일당은 다른 돈

한 잔의 하루에 있는 매출·재료비·팁은 **가게의 돈**이에요. 직원이 받는 건 일당이에요.

- 퇴근 화면의 큰 숫자는 **일당**이에요. 매출은 "오늘 내가 만든 가게 매출"로 따로 보여 줘요.
- 팁은 일당에 더하지 않아요. 손님이 얼마나 만족했는지 보여 주는 표시로만 써요. 우리나라 카페는 대부분 팁을 받지 않기 때문이에요.
- "매출 − 재료비 = 내 수익" 같은 사장의 계산은 쓰지 않아요. 이 앱은 창업이 아니라 **직업 선택**을 위한 체험이에요.
  - 다만 "내 한 잔에 재료비가 얼마 들었나"를 보여 주는 건 좋아요. 일하는 사람도 가게 사정을 아는 건 직업 이해에 도움이 돼요.

### 일한 시간

체험은 몇 분이지만, 앱 안의 시계로 **하루 근무**를 나타내요.

- 앱마다 `shift { start, end, breakMin }` 을 정해요. 예: 바리스타 08:30–17:30, 쉬는 시간 60분.
- 앱 안에서 일이 밀려 늦게 마치면 그만큼 연장 근무예요. 남아서 마칠지 다음 사람에게 넘길지는 학생이 고르게 하면 좋아요.

## 2. 퇴근길 돌아보기 (꼭 지킬 것)

1. 하루 동안 학생이 한 일 가운데 **순간**을 4~8개 모아요. 순간마다 `label`(“붓는 양을 맞춘 순간”)과 흥미 유형 `type`(R·I·A·S·E·C)을 붙여요.
   - 쉬는 순간처럼 일이 아닌 순간은 `type: null` 로 둬요.
   - 한 직업의 하루에 흥미 유형이 **4가지 이상** 나오게 해요.
2. 학생이 💛 끌린 순간 하나와 🪨 버거운 순간 하나를 골라요.
3. "그 순간의 일은 ○○형 쪽의 일이에요"라고 알려 줘요. **적성 판정이나 직업 추천은 하지 않아요.**
   - 문구는 `RIASEC[type].name` 과 `.what` 을 써요.
   - "순간 하나로 나를 정할 수는 없어요. 여러 직업을 해 보고 흥미검사와도 견주어 보세요"를 함께 보여 줘요.

바리스타 순간의 예:

| 순간 | 유형 |
|---|---|
| 원두를 갈고 에스프레소를 추출한 순간 | R |
| 손님 취향에 맞춰 붓는 양을 조절한 순간 | I |
| 주문을 받고 손님과 이야기한 순간 | S |
| 컵을 씻어 선반에 정리한 순간 | C |
| 테이블을 닦아 다음 손님 자리를 준비한 순간 | R |
| OPEN 간판을 뒤집고 하루를 연 순간 | E |

## 3. 출근 기록 (꼭 지킬 것)

하루를 마치면 `makeRecord()` 로 기록 하나를 만들고, `checkRecord()` 가 빈 배열인지 확인한 뒤 `saveRecord()` 로 저장해요.

```js
{
  v: 1,
  app: 'barista-day',                 // 앱 이름
  date: '2026-11-14',
  job: { id: 'barista', name: '바리스타', careernet: '180' },
  place: 'cafe',
  shift: { start: '08:30', end: '17:30', breakMin: 60 },
  pay: { annual: 3004, wageYear: 2021, wageBasis: '음료조리사', hourly: 11980, floored: false,
         workedMin: 495, shiftMin: 480, overMin: 15, base: 95840, overtime: 4490, total: 100330 },
  ending: { name: '손님 취향을 맞춰 간 하루', icon: '☕' },  // 퇴근길 한 줄. 이름은 앱마다 자유
  like: { label: '붓는 양을 맞춘 순간', type: 'R' },
  hard: { label: '컵을 씻어 선반에 정리한 순간', type: 'C' },
  extra: { sales: 13500, materials: 2150, drinks: 3 },     // 앱마다 따로 보여 줄 것. 일당에 섞지 않음
}
```

- 저장 칸 이름은 `workday-records-v1` 이에요. 같은 주소에 올린 앱끼리는 **지갑(누적 일당)을 함께** 써요.
- 학생 이름, 학번, 연락처는 기록에 넣지 않아요. 교사용 결과 모으기를 만들 때 따로 정해요.
- 기록 모양을 바꿔야 하면 `v` 를 올리고, 이 문서와 `workday.js` 를 함께 고쳐요.

## 4. 함께 지킬 태도

- 등장인물과 기록은 모두 가상이에요.
- 전문 업무(의료, 레시피의 정답 등)를 정답처럼 가르치지 않아요. 맛 모델처럼 단순하게 만든 것은 "단순화한 체험"이라고 밝혀요.
- 폰 터치로 끝까지 할 수 있어야 해요. 3D가 안 되는 기기에서도 막히지 않게 해요.
- 직업끼리 일당 순위를 매기지 않아요.

## 5. 깃으로 소통하는 방법

| 누가 | 브랜치 | 고치는 곳 |
|---|---|---|
| Claude | `claude/focused-davinci-c033wr` | `career-day/`, `shared/` |
| Codex | `codex/barista-day` (Claude 브랜치에서 갈라져 시작) | `barista-day/` |

- **남의 폴더는 고치지 않아요.** 그러면 두 브랜치를 합칠 때 충돌이 나지 않아요.
- `shared/` 는 Claude가 고쳐요. 바꾸고 싶은 게 있으면 Codex는 게시판에 적어요.
- 게시판은 각자 자기 파일에만 써요. 날짜를 적고 **아래에 덧붙이기만** 해요.
  - Codex → `barista-day/BOARD.md`
  - Claude → `shared/BOARD.md`
- 작업을 시작할 때 상대 브랜치를 가져와 게시판부터 읽어요.

```bash
git fetch origin claude/focused-davinci-c033wr codex/barista-day
```

- 바리스타는 빌드 없이 `dist/` 를 바로 웹 서버로 열어요. 그래서 `shared/workday.js` 를 **그대로 복사**해 `barista-day/dist/shared/workday.js` 에 두고, `./shared/workday.js` 로 import 해요.
  - 복사본이 원본과 같은지는 `node shared/test.mjs` 가 확인해요.
  - 원본이 바뀌면 Claude가 게시판에 알리고, Codex가 다시 복사해요.
- 두 브랜치를 언제 합칠지는 선생님이 정해요.

## 6. 고치는 순서 (`shared/` 를 바꿀 때)

1. `shared/BOARD.md` 에 무엇을 왜 바꾸는지 적는다.
2. `workday.js` 와 이 문서를 함께 고친다.
3. `node shared/test.mjs` 와 `career-day` 의 `npm test` 를 통과시킨다.
4. 게시판에 "복사본을 갱신해 주세요"를 적는다.
